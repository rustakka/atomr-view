# Troubleshooting atomr-view

This skill helps you debug common issues in the `atomr-view` system.

## Common Issues

### UI Stalls / Lag

- **Cause**: Blocking the UI thread with long-running computations.
- **Fix**: Offload heavy work to actors in the `ActorSystem`. The UI thread
  should only handle rendering and polling the bridge.
- **Check**: Look for `tokio::spawn` calls in the backend event loop.

### Reconciliation Mismatches

- **Cause**: Reusing `SceneKey`s for different node kinds or structures.
- **Fix**: Ensure `SceneKey` is unique per logical node. If a node's kind
  changes, use a new key or the reconciler will attempt an illegal mutation.
- **Check**: Inspect the `ScenePatch` sequence generated by `diff()`.

### Python-Rust Boundary Errors

- **Cause**: Type mismatches in `PropertyValue` or `NodeKind`.
- **Fix**: Use the explicit enum constructors in Python (e.g.,
  `view.PropertyValue.String("val")`) rather than passing raw primitives.
- **Check**: Look for `PyErr` in the logs.

### Deadlocks

- **Cause**: Recursive `ask` calls or circular actor dependencies.
- **Fix**: Use `tell` where possible. Prefer `watch` for cleanup rather than
  waiting for explicit replies.
- **Check**: Bridge actor mailbox size; if it grows indefinitely, the
  backend is likely stalled.
